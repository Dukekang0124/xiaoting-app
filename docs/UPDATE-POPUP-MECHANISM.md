## 一、先回答你最关心的：为什么你手机上收不到

结论先行：**功能早就写好了（v1.6.2），但它救不了你已经装上的 1.4.6** —— 这是 Capacitor 架构的硬约束，不是漏做。

### 1.4.6 是一条「更新死」的装机包（已取证）

| 事实 | 证据 |
|---|---|
| 1.4.6 的硬编码兜底常量就是它自己 | `git show v1.4.6:js/update.js` → `export const LATEST_VERSION = '1.4.6';`（第 41 行） |
| 它在 APK 里取数走**绝对线上地址**（跨域） | 同文件第 203 行 `cands.push({ url: apiBase() + p })`；`apiBase()` 在原生壳里返回线上域名 |
| 线上 `/version.json` **不返回任何 ACAO 头** | 实测 `curl -H "Origin: https://localhost"` → `HTTP/1.1 200` + `Content-Type: application/json`，**无 `Access-Control-Allow-Origin`** |
| ⇒ 跨域 fetch 被浏览器直接拒 | 1.4.6 的唯一通道挂掉 |
| ⇒ 落硬编码兜底 ⇒ `cmpVersion('1.4.6','1.4.6') = 0` | **弹窗一次都不会弹** |

**死结的形状**：老包读不到线上清单，老包的兜底值恒等于它自己 ⇒ 永远"你已是最新"。

> 也就是说**线上已经比你的 1.4.6 高两个版本**，但 1.4.6 的代码物理上看不到它。

## 二、实现思路

### 2.1 为什么必须有三条通道（而不是一条）

APK 里跑的是 WebView，页面地址是 `https://localhost`，而更新清单托管在**线上域名**。这里有一个无解的对立：

| 取数方式 | 在 APK（WebView）里 | 在网页里 |
|---|---|---|
| **相对路径** `/version.json` | 打到本地 assets → **404** | ✅ 正常 |
| **绝对地址** `https://…host/version.json` | 打线上 → **跨域** → 线上无 ACAO ⇒ **被拒** | ✅ 正常 |

单靠一条通道，APP 里和网页上**总有一边是死的**。所以三条通道并行，谁先拿到新版本谁顶上：

```
/api/version/latest  →  /version.json  →  /version-latest.js（脚本形态）
     （线上有 Node 才通）     （清单本体）        （🔴 关键：绕开 CORS 的那条）
```

### 2.2 脚本通道为什么能绕开 CORS（这是整个方案的根）

`<script src>` 是**经典脚本标签**，从诞生起就允许跨源**执行**，浏览器不要求"读得回响应体"。
我们把清单再发一份脚本形态，内容只有一句：

```js
window.__VERSION_MANIFEST__ = { latest_version: "1.6.2", release_notes: [...], apk: {...} };
```

- 跨域加载 → 照样执行 → 副作用变量写进 `window` → 我们读它。
- **不需要托管方给任何响应头**，也不必换托管平台（这是选这条路而不是"求着托管加 ACAO"的原因）。
- 产物由 `scripts/version-manifest-js.cjs` 唯一发生器产出，`build:web.mjs` 与 `server.cjs` 共用同一份，不会两边漂移。

### 2.3 三条通道并行取**大者**，不是"第一个成功就返回"

```js
Promise.allSettled(cands.map(fetchOne))
  → 取 cmpVersion 最大者；并列时优先站点通道(/version.json)
```

为什么必须取大者：网关/CDN 是多节点不一致的，**旧缓存节点返回的也是合法 200**。"第一个成功就返回"会采信旧快照，于是发版后用户半天收到不了提示（v1.3.5 实测过清单在旧桶里停 18 小时）。

## 三、版本检测逻辑

### 3.1 触发时机

| 时机 | 行为 |
|---|---|
| **App 启动** | `app.js:3615 update.initUpdate()` → 立即检测一次 |
| **从后台回前台** | `visibilitychange` 且 `!document.hidden` → 再检测一次（用户去微信回来可能正好发了新版） |
| **手动点「检查更新」** | 永远可用，且**必须永远有回话**（v1.4.0 的教训：点了没反应 = 用户判定功能坏了） |
| **每月 1 号** | 月度情绪复盘弹窗（与更新弹窗互相隔离，见注意事项） |

### 3.2 判定

```
latest = 三条通道里 cmpVersion 最大者（全挂 → 硬编码兜底 FALLBACK）
cmp = cmpVersion(latest, current)
```

| 情况 | 结果 |
|---|---|
| `cmp > 0` | 弹更新弹窗（这就是我们要的） |
| `cmp === 0` | 不弹；手动检查时如实说「已经是最新」 |
| 三条通道全挂 | 落硬编码兜底，**文案不许再撒谎**（见 4.3） |

**硬编码兜底取值规则 = 线上与硬编码「取较大者」**：直接覆盖会在发下一版时把更新功能反向锁死（线上 1.5.0、硬编码 1.4.2 ⇒ 永远不提示）。

**每个候选的失败原因单独记录**：排障时不再只剩一句 `fetch_failed`，链路诊断页能直接看到是哪条通道死的、死的原因是什么。

**防网关缓存**：每个清单请求都带 `?cb=时间戳+随机数`（v1.4.6 起）。`cache:'no-store'` 只约束浏览器缓存，管不了网关按 (路径, Accept-Encoding) 分桶。

**「稍后再说」按版本记忆，不按天**（v1.4.3）：用户点过的是「这个版本我暂时不装」，不是「今天不装」；`xiaoting:update_snooze_day` 按天会被第二天继续弹。写 `xiaoting:update_dismissed_ver`。手动检查永远可用，强制更新不受影响。

## 四、弹窗文案与交互设计

### 4.1 弹窗结构（v1.6.2 实际渲染）

```
┌────────────────────────────────┐
│        [墨小溟 IP/happy 104]    │
│           有新版啦              │
│  墨小溟更新到了 v1.6.2          │  ← 版本号（你要的）
│  ──────────────────────────    │
│  · 更新说明第一条               │  ← 更新说明（release_notes，你要的）
│  · 更新说明第二条               │
│  · 更新说明第三条               │
│  ──────────────────────────    │
│  点「立即更新」会弹出安装指引…   │  ← 副文案（按平台分叉）
│  ┌──────────┐ ┌────────────┐  │
│  │ 立即更新 │ │  稍后再说  │  │
│  └──────────┘ └────────────┘  │
└────────────────────────────────┘
```

### 4.2 文案表（按平台分叉，不是一套话说全部人）

| 位置 | 文案 | 理由 |
|---|---|---|
| 主标题 | `墨小溟更新到了 v${latest}` | 版本号必须出现在标题，用户第一眼要看的是"差多少" |
| 徽标 | `有新版啦` | 沿用 IP 语气，不做系统升级那种机械风 |
| **副文案 · APP（apk）** | `点「立即更新」会弹出安装指引，跟着 3 步就能装上最新版。` | 安卓必须给安装步骤，否则用户以为点了没反应 |
| **副文案 · 网页** | `点击立即更新，墨小溟会自动刷新到最新版。` | 网页刷新即新版；**但 APK 里说"刷新"是错的**（壳内资源刷新不变），所以必须分叉 |
| 微信内 | `微信里没法直接更新，点右上角「···」在浏览器中打开，就能装最新版啦。` | 兜底路径，且说清下一步 |
| 主按钮 | `立即更新` | |
| 次按钮（仅非强制） | `稍后再说` | |
| 强制更新 | 只有主按钮，遮罩不关、ESC 不关 | `update-overlay--force` |

> 🔴 **这条分叉是踩出来的坑**：同一份代码在 App 里和网页上正确行为相反 —— App 里说「刷新页面」是错的（刷了也不会变），网页上给安装包也是错的。分象限测试（`audit-update-quadrant`，15 断言）就是为了卡死这事。

### 4.3 兜底文案：不许撒谎（v1.4.6 那句真机谎言的回归护栏）

你截图里那句「**暂时没连上更新服务，按本地记录你已是最新 v1.4.6**」是产品说谎。
硬编码常量既证明不了有新版、也证明不了没新版，却把故障说成了结论。

现在改成：

> `暂时读不到更新服务，无法确认有没有新版本（当前 v1.6.2）；联网后再点一次「检查更新」`

独立成断言：探针里有一条**反向断言**——读不到清单时不允许再出现「已是最新」字样。

### 4.4 交互细节

| 行为 | 规则 |
|---|---|
| 点遮罩 | 非强制 = 稍后再说；强制 = 不关 |
| ESC | 同上 |
| 重复弹 | 同一次 session 内 `lastShownKey` 防前台/后台来回切重复弹 |
| 与月度弹窗共存 | 月度弹窗有独立隔离键 `localStorage['monthly:done_<YYYYMM>']`，两者互不吞（见注意事项） |

## 五、下载安装流程

```
点「立即更新」
   ↓
installApkInApp(url, version)
   ↓
① fetch 下载 → 校验 ZIP 魔数 PK\x03\x04（validateApkBytes）
   🔴 SPA 式托管对不存在的路径会回落 index.html 并返回 200
      （实测 GET …/apk/Xiaoting-v9.9.9-release.apk → 200 / text/html / 8491 B）
      ⇒ 只看 res.ok + 体积会把 HTML 写成缓存再调起安装器，
        用户看到"已唤起安装"然后系统报「解析包时出现问题」
      ⇒ 「不是安装包」是**独立错误分支**，绝不回落成"用下载方式"
   校验失败 → 页面 + 诊断记 installer_cors_blocked / not_an_apk
   ↓
② 下载到缓存目录 → 换 content:// URI
   ↓
③ 调起系统安装器（ACTION_VIEW + REQUEST_INSTALL_PACKAGES）
   🔴 插件 `file-opener` 的 Android 包名是 com/ryltsov/alex/plugins/file/opener
      （不是 capacitor-community/…，按后者搜会得到假的"没进包"结论）
   ↓
④ 拿不到插件 → 回落到「下载 + 通知栏」流程（不卡住）
```

**安装器失败要单独识别是跨域造成的**并记 `installer_cors_blocked`，别笼统写成"安装失败"。

## 六、后续统一走弹窗更新，必须留意的事项

### 6.1 发布面（每次发版都要过）

1. **站点 `www/` 必须一起发** —— 本轮线上还停在 1.6.1，`/version-latest.js` 404、`js/update.js` 无脚本通道。光提交代码线上还是老样子。**APK 发了、站点没发 = 用户永远收到「已是最新」**（v1.4.1 踩过）。
2. 发版收尾顺序：CI 出包 → 取回 `apk-dist/` → `node scripts/build-web.mjs` → 发布 `www/` → 线上多采样复核。
3. `server/version.json` 的 `apk.md5` / `apk.size` 由 CI 回填，别手改；清单 `latest_version` 与七处版本号必须同值。
4. 🔴 **CI 回填会往 `history` 顶部插当前版本条目（不管是否已存在）** ⇒ 发版时**不要**手工 unshift，否则 history 里两个同版本，`live-update-popup` 取 `history[1]` 当旧包会假红。
5. 🔴 **「发布 `www/`」这一步在当前仓库里没有 npm 脚本**（`package.json` 只有 `start`/`build:web`/`cap:*`/`apk:debug`）⇒ 走 WorkBuddy 发布通道把 `www/` 目录推上去、复用已有 appId `wbapp_UIbhopeTjkEWVQhMQ0Q0Ia`，**域名与分享链接不变**（v1.6.2 实测 10:24 发布、10:25 三探针全绿）。别默认"push 了就上线了"。
6. 发版后**必须等线上收敛再判定**：网关是多节点分桶缓存（gzip/br/zstd/identity 各一桶），Fresh 发布要裸路径 + 真实浏览器头 + 多桶采样（L3 探针自带分桶诊断）。刚发完立刻测可能拿到旧桶，别急着回滚。

### 6.2 升级路径（最容易忘）

5. **任何 `js/` 下的产品代码改动，都必须随下一次出包落地** —— Android WebView 读的是壳内 `assets/public/` 那份 `www/` 副本，不是网页版。本机没有 Java/Android SDK，APK 只能由 CI 出包。
   ⇒ **「加了个弹窗但没出包」等于没加**。改完先问一句：这版包出了吗？
6. **老装机包是"更新死"的**：1.4.4/1.4.5/1.4.6 这批读不到线上清单（无 ACAO + 兜底恒等自己）。对新老用户要分开说：老用户只能手动装一次，之后自动。
7. 版本号**七处同步**：index.html(SSOT) / sw.js CACHE / manifest / package.json / app.js 兜底×3 / update.js 的 `LATEST_VERSION` + `FALLBACK_APK_URL` / server.cjs / server/version.json。发版前 grep 旧版本。
8. 新前端资产要**四处同步**：`build-web.mjs` 的 `DIRS/FILES`、`server.cjs` 白名单、`sw.js` ASSETS、`www/` 产物。漏 ASSETS ⇒ 离线 404（v1.4.1 的 `js/notify.js` 就漏过）；漏白名单 ⇒ 构建归类断言直接失败。
9. `sw.js` 要**排除** `/version-latest.js`（故意不预缓存：预缓存比 stale 更彻底，会锁死旧清单）。

### 6.3 测试面（判据落错通道，会制造假红假绿）

10. 🔴 **`page.route('**/version.json')` 匹配不到 `/version.json?cb=...`**（实测命中 0）。因为 `fetchJson`/`loadScript` 给每个清单请求都加 `?cb=`（破网关缓存桶）。**凡拦清单请求的 route 必须写 `**/x*` 带尾部星号**。漏了：abort ⇒ 场景没发生 ⇒ 假红；fulfill ⇒ 注入数据到不了页面 ⇒ **假绿**。
11. 🔴 **改 hash 不重载页面**（`location.hash=` / `page.goto('#/x')`）。要让"取数失败"分支真跑起来必须 `page.reload()`，且**先 goto 落定 hash 再 reload**，顺序反了会重载上一个页面。
12. 🔴 **跑自测前先核每个端口 `/api/health` 的版本**。静态文件每次读盘（页面是新的），但 `/api/health` 读内存常量 —— 上一会话遗留的僵尸进程能让 4174 报 1.5.0、4175 报 1.6.1。**在这类服务上跑出的"全绿"不可信。**
13. 判"下载到的包对不对"不能只看 `res.ok` + 体积：必须校验 ZIP 魔数；"不是安装包"是独立分支，绝不回落"用下载方式"。
14. 造 CORS 场景要**显式给一个对不上的 Origin**（Playwright 的 `route.fulfill` 会给跨源响应自动补 ACAO，照抄 `*` 等于把线上约束抹掉、测出假通）。并且先加**自证守卫**：先证明跨源 fetch 确实被 CORS 拒。
15. 探针失败项要打**名字**，别只打 ❌（月度探针原来只印 ❌，为定位两条红多花两轮）。
16. 判"某通道被探过"别用结尾锚定正则配带 query 的 URL，存之前先 `u.replace(/\?.*$/,'')`。
17. 判"改没生效"看代码里的构建标记，别信时间戳/文件名。

### 6.4 用户体验与运营

18. 更新说明（`release_notes`）是**用户看见的东西**，不是发版记录。每条要能独立看懂（"这次变了什么对我有什么好处"），不要写"fix some bugs"。
19. 强制更新（`force_update`）只用于安全线，日常别开 —— 强制弹窗关不掉，用户会卸载。
20. 兜底永远要有：读不到清单就如实说读不到，**不允许拿本地常量硬说"已是最新"**（这条已成回归断言）。
21. 「稍后再说」按**版本**记忆；同一版本别天天弹。
22. 月度情绪复盘弹窗会盖住页面（`.monthly-overlay` 全屏 `aria-modal`），**新增探针/自动化点击前必须先把 `monthly:done_<YYYYMM>` 置 1**，否则每月 1 号集体假红（本轮已统一补 27 处）。
